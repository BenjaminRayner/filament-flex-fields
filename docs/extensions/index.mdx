Build an extension for your own application or distribute it as a Composer package.
One family can provide a form field, a table column and an infolist entry, while
sharing the same value format and stylesheet. Add only the surfaces you need.

You can also attach [typed usage guidance](/docs/extensions/ai-guidance) to each
component. AI tools can discover its actual renderer, declared examples, storage
notes and verification steps without a separate catalog or playground page.

## Choose a starting point

<Tabs>
  <Tab title="For one application">
    Use the generated package as a local Composer path repository. It keeps your
    provider, views, classes and build together, and you can reuse the same package
    in another application later. Start with the [quickstart](/docs/extensions/quickstart).
  </Tab>
  <Tab title="For distribution">
    Generate the same starter, choose your package identity and license, build the
    assets, then ship its Composer metadata, PHP classes, views, manifest and referenced
    release directory. Read [deployment](/docs/extensions/deployment) before publishing updates.
  </Tab>
  <Tab title="For an existing package">
    Keep your public field API and register its typed definitions. The
    [registration guide](/docs/extensions/registration) describes local-file registration;
    [package contracts](/docs/extensions/packages-and-families) add manifest-backed families.
  </Tab>
</Tabs>

## What you can build

| Goal | Guide |
| --- | --- |
| A form field with its own PHP configuration and view | [Form fields](/docs/extensions/fields) |
| A table cell and read-only infolist presentation | [Columns and entries](/docs/extensions/columns-and-entries) |
| A parent containing configurable Select or Text Input children | [Composition](/docs/extensions/child-select) |
| Application-provided relations or query callbacks on a child | [Full child PHP API](/docs/extensions/child-php-api) |
| A family selected through saved JSON schemas | [Dynamic schemas](/docs/extensions/schema-adapter) |
| A custom dialog or drawer using FLEX controls | [Custom surfaces](/docs/extensions/surfaces) |
| Optional editors, workers, fonts or WASM | [Asset build](/docs/extensions/build) |
| Package names, tokens, translations and RTL | [Appearance](/docs/extensions/appearance), [locales](/docs/extensions/locales) |
| A safe upgrade of saved configuration and values | [Migrations](/docs/extensions/migrations) |

## Read examples in context

The quickstart uses the generated `Acme\Summary` package. The focused guides use
an illustrative `Acme\Rating` family to show independent choices. Class names such
as `RatingField` belong to your extension; they are not built-in FLEX classes.
Snippets extending a provider or adapter are marked by their surrounding instructions.

<Note>
  Registration describes assets and supported surfaces. It does not copy a child's
  HTML, save records, or replace your application's authorization. Render the actual
  child class and keep validation and write policies on the server.
</Note>
